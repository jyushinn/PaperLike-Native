# PaperLike 13.3K 彩色版与黑白版串口协议

## 已静态验证的帧

- 请求是 24 个 ASCII 字符：`5FF5` + 两位命令 + 两位参数 + 12 个 `0` + `A0FA`。
- 示例：命令 `0x02`、参数 `0x03` 编码为 `5FF50203000000000000A0FA`。
- 响应也是 24 个 ASCII 字符；前 12 个字符依次为四位头、封装命令、响应命令、请求参数和值，随后为 8 个 `0` 和四位尾。
- 头为 `0x5FF5`；数值字段均为两位十六进制。
- 已定位命令：`01` 对比度、`02` 模式、`03` 强刷、`04` 速度、`07` 前光模式、`08` 色温、`09` 亮度、`0A` 状态查询、`20` 视频处理板保活、`F0` 识别响应。
- 状态查询使用命令 `0A`，参数至少包含 `01`、`02`、`07`、`08`、`09`、`13`。
- `0A 10` 返回 MCU：`0x10/0x11` 表示无前光，`0x30/0x31` 表示有前光。
- `0A 13` 返回型号族：`0x01` 是 13.3K 彩色版，`0x02` 是 13.3K 黑白版。
- 彩色版实机启动采集确认：`5FF5F00A103011100001A0FA` 表示 MCU 为 `0x30`；`5FF5F00A130100000000A0FA` 表示型号族值为 `0x01`。
- 查询响应中，封装命令为 `F0`、响应命令为 `0A`，其后两字节分别回显查询参数和值。
- 13.3K 彩色版和黑白版共用模式映射：网页 `02 06`、文字 `02 02`、图像 `02 03`、动态 `02 07`。模式切换会由显示器异步推送其推荐对比度。
- 2026-10-08 彩色实机单变量采集：网页写入 `02 06`，模式查询 `0A 02` 返回 `01`；文字、图像、动态分别读回 `02`、`03`、`07`。读回 `01` 只解码为网页，写入仍用 `06`，不改配置存储值；兼容既有 `06` 读回。黑白型号此差异尚未实机验证。
- 官方 V2.0.3 客户端使用 `04 01` 至 `04 05` 设置“快速”至“快速++++”。固件没有提供速度读回值，因此客户端连接后将速度标为“未读取”。
- 无前光机型不查询 `0A 07`、`0A 09`、`0A 08`，也拒绝发送对应写命令；有前光机型才开放前光界面和自动化。
- 原厂 V2.0.3 在型号识别完成后立即发送 `20 01`，随后约每 2 秒重复一次；设备回复 `F0 20 00 00`。停止保活后显示器可能进入“No signal”，因此兼容客户端在连接期间复制该节奏，断开时停止。
- 2026-10-08 彩色实机前光关闭后，固件约0.25/0.35秒仍推送亮度/色温事件，此期间发出的模式查询没有响应；约0.5秒超时后重发同一只读查询成功。状态复核复用握手最多三次查询机制，控制写入仍不自动重试。
- 串口波特率为 115200。
- “抖动”与“显示增强”不走串口：原客户端分别写显示驱动属性 `enableDither` 与 `uniformity2D`。

## 证据位置

- 请求编码：`-[ORSSerialPort sendDataWithCommand:andOptional:]` 中的格式串 `%.04X%.2X%.2X%.12X%.4X`，常量头尾为 `0x5FF5` 和 `0xA0FA`。
- 响应解码：`-[ORSSerialPortHelper serialPort:didReceiveData:]` 中的格式串 `%04X%02X%02X%02X%02X`。
- 命令和型号映射：官方 V2.0.3 客户端的控制器与设备名称映射函数。
- 波特率：串口初始化传入十六进制 `0x1C200`，即 115200。
- 显示驱动属性：`Stillcolor` 调用 `IORegistryEntrySetCFProperty`。

## 验证规则

彩色版已完成实机采集；黑白版目前是官方客户端静态核验加模拟协议测试，仍需黑白
实机确认。每个改变状态的命令必须由单变量采集确认，未确认的参数范围不进入正式
界面。原始采集保存在被 Git 忽略的 `.captures/`，仓库只保存去除环境信息后的
语义测试夹具。
