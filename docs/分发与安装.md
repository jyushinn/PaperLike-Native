# 安装与分发

## 安装

将“PaperLike Native.app”放入“应用程序”文件夹后打开，再按需要启用登录项和系统权限。

默认预览包使用ad-hoc签名，没有通过Apple公证。若系统阻止打开，请先确认下载来源与校验值，再按macOS“隐私与安全性”中的提示处理。不要关闭系统安全保护。

触控需要辅助功能权限；修改系统显示辅助功能另需自动化权限。应用标识或签名改变后，权限可能需要重新授予。

## 升级与恢复

从早期本地版本迁移到应用标识为 `org.paperlike.native` 的公开版时：

1. 在原应用中导出配置JSON，然后退出原应用。
2. 安装并打开新版，在“场景 → 备份与恢复”中导入JSON。
3. 检查配置和系统权限，再恢复自动控制；登录项按需要重新启用。

恢复向导中的原始备份plist保留异常数据供排查，不能直接当成配置JSON导入。请自行妥善保存导出文件，不要随问题报告公开上传。

## 构建与校验

```sh
Tools/test.sh
zsh Tools/test-release-tools.sh
Tools/package-app.sh
cd dist
shasum -a 256 -c SHA256SUMS
```

构建要求Swift 6.2+和兼容的macOS SDK；发布脚本默认生成ARM64应用。完整Xcode提供Icon Composer编译与导出工具，缺少这些工具时使用仓库内的兼容图标。

输出为ZIP、DMG和SHA256SUMS。同一版本重新打包会覆盖原产物。校验值用于检查文件完整性，不能单独证明发布者身份。

## 正式签名与公证

维护者可使用自己的Developer ID证书和已配置的钥匙串公证凭据：

```sh
PAPERLIKE_SIGNING_IDENTITY='Developer ID Application: Your Organization (TEAMID)' \
PAPERLIKE_NOTARY_PROFILE='your-existing-keychain-profile' \
Tools/package-app.sh
```

仅设置签名身份会签名但不公证。公证流程会等待Apple接受提交，再将票据附加到应用与DMG，最后生成校验值。任何一步失败时都应停止发布。不要将证书、密码或密钥加入仓库。

参考：[Apple公证文档](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)。

## 发布检查

- 确认版本、变更记录、支持范围与下载文件一致。
- 在全新检出中运行测试与Release构建，并检查远程CI结果。
- 按[设备测试清单](hardware-checklist.md)验证相关改动。
- 只上传明确标注签名状态的应用包和校验文件。

当前CI检查测试、打包工具和Release构建，不包含证书，也不自动发布。远程runner工具链路径可能变化，需在首次运行时确认。
